# SUBMUNDO multiplayer / Render

## Architecture

SUBMUNDO keeps **MongoDB as the authoritative persistent store**. Multiplayer
delivery is split from persistence:

- FastAPI on Render: authenticated HTTP mutations + WebSocket endpoint.
- Render Key Value (Valkey/Redis compatible): pub/sub between API instances.
- MongoDB: players, operations, chat history, alliances, PvP, economy and saves.
- Web/Android clients: REST for authoritative writes, WebSocket for live events.

The WebSocket endpoint is:

```
wss://<api-host>/api/realtime/ws?token=<access-token>
```

Clients never mutate money, inventory, missions or PvP results over WebSocket.
They use the existing HTTP API; WebSocket only distributes notifications. This
keeps the server authoritative and prevents forged multiplayer state.

## Realtime events currently emitted

- `realtime.ready`
- `realtime.subscribed`
- `presence.changed`
- `city.chat.message`
- `city.pvp.challenge`
- `city.pvp.resolved`

Channels supported: `world`, `city`, `chat`, `pvp`, `alliance`.

## Render

`render.yaml` provisions the API and a Frankfurt Key Value instance. The only
required deployment secret that cannot live in Git is `MONGO_URL`. Optional
production values are `GOOGLE_WEB_CLIENT_ID`, `ADMIN_EMAIL` and
`ADMIN_PASSWORD`.

The API uses the internal `REDIS_URL` generated by Render, so pub/sub traffic
does not traverse the public internet.

Health checks:

- `GET /api/health`
- `GET /api/realtime/health`

## Scaling rules

MongoDB remains the source of truth; Redis/Valkey is disposable notification
infrastructure. Losing Redis may delay live notifications but must never lose
money, inventory or permanent progress.

One API instance works without Redis using local delivery. Multiple instances
require `REDIS_URL` so all connected clients receive the same event stream.

## Android / Google Play

Build the app with `REACT_APP_BACKEND_URL=https://<render-api-host>`. The
frontend helper in `frontend/src/lib/realtime.js` automatically converts the
HTTPS API URL to WSS and reconnects after mobile network changes.
